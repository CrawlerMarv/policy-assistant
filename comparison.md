I compared the three approaches on 20 test questions against the database of 98 policies: seven questions use a policy's own wording, seven are paraphrased, one asks for a detail the relevant policy does not specify (the number of sick days), and five concern topics no policy covers. An answer counted as unsupported if it cited a policy that does not exist, answered a question no policy covers, or contained figures absent from the cited policy. The rules-based BM25 keyword search answered all seven directly worded questions correctly in under a millisecond and without any tokens, but it found the right policy for only two of the seven paraphrased questions, because it can only match words that literally appear in a policy ("jeans" never leads to the Dress Code Policy). It also produced the only unsupported answer in the test: asked about a home-internet allowance, it returned the Internet Usage Policy, which contains no such allowance. Overall it was correct on 13 of 20 questions (65%). Both language-model approaches used Gemini 3.5 Flash-Lite with the same instruction to answer only from the supplied policies. Each identified the right policy for all 15 covered questions, declined all five uncovered ones and produced no unsupported answer (100%).

Since accuracy does not separate the two language-model approaches, the decision rests on cost and scalability. Without a vector index, every request contains the entire database, which averaged 2,128 tokens and 0.91 seconds per question. With the vector index, only the three most similar policies are retrieved and sent, which reduced this to 290 tokens (86% fewer) and 0.78 seconds. Because the full-context prompt grows linearly with every policy added while the retrieval prompt stays roughly constant, this gap widens as the policy database grows. I therefore prefer the language model with a vector index, which is also the approach used by the Slack bot. Its main risk lies in retrieval: if the relevant policy is not among the three candidates, the model cannot find it. The small test set did not expose this weakness, and the automatic checks cannot detect answers that are merely loosely related to the question; in a live test, for instance, the approach without an index answered a question about taxi expenses with the deadline for submitting travel receipts. The results should therefore be read as indicative rather than conclusive.
